# Hiyori 2D: reference analysis and implementation handoff

Reviewed 2026-09-29. Scope: the eight links in the latest reference list, the puppeting comparison, and the earlier Inori and shinshin86 examples (11 distinct supplied URLs). X post text was inspected in an authenticated browser. Linked StandRig documentation and official Hi3D/Tripo documentation were checked separately. Video observations are sampled visual observations, not a frame-by-frame or audio assessment. No third-party prompt is an instruction to execute or install anything.

## Decision

Keep Hiyori 2D and preserve her appearance. Prioritize rebuilding parts, attachments and deformation over adding gesture counts. Four-view art is a consistency reference; it is neither an editable rig nor a sufficient set of deformation targets. Author model changes with Claude Opus 5.5 at max effort. Jev will select only accepted, closed action IDs; audio retains mouth-opening ownership.

## Especially relevant continuation

[Sayaka 8/11](https://x.com/sayaka_aiart/status/2103669378265022873) explicitly covers shoulder/clavicle pivot positions, thumb direction, palm deformation and testing in the eventual playback app. It says eliminating every internal intersection can produce unnatural crushed joints. Transfer that distinction: reject holes/inversions and bad visible silhouettes, while allowing intentional hidden overlap. This is a creator's reported workflow, not a universal numerical rule.

The thread's remaining visible stages cover geometry cleanup, UV/texture work, body rigging, head/body assembly, expressions/gaze, secondary motion and final VRM playback. Only steps 1, 2 and 8 were expanded in full; other stages were read as their visible summaries. The 2.5-minute parent video was not exhaustively analyzed.

## Official source cross-checks

- [StandRig](https://github.com/sayaka-aiart/StandRig): independent PSD-to-JSON runtime, not a moc3/cmo3 exporter. Use concepts, no migration/install commitment.
- [StandRig operations](https://github.com/sayaka-aiart/StandRig/blob/main/docs/OPERATIONS.md): parameter-specific vertex offsets, two-parameter correction keys and deformable attachment pins.
- [StandRig API](https://github.com/sayaka-aiart/StandRig/blob/main/docs/API.md): separate join, exposed-art and triangle-deformation QA.
- [StandRig visual reference gate](https://github.com/sayaka-aiart/StandRig/blob/main/AI_OPERATING_GUIDE.md): neutral, intermediate, extreme and connection reference art; a broken current render is not the target.
- [Hi3D create task](https://docs.hi3d.ai/en/api/api-reference/list/create-task): separate multi-view inputs, maximum four, front/back/left/right order. Exported FBX alone does not establish a rig. Automatic rigging was not confirmed in the inspected API.
- [Tripo multi-view](https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/standard): front plus up to three other views; consistent subject. Named views preferred; legacy array order differs from Hi3D.
- [Tripo rig check](https://developers.tripo3d.ai/en/docs/animations-rig-check) and [rig](https://developers.tripo3d.ai/en/docs/animations-rig): rig suitability and skeleton generation are separate operations from mesh creation.

## Concrete Hiyori correction contract

1. Preserve original Core evaluation and neutral artwork. Rework only the isolated v2 prototype. No production app, paid API or personal-data changes.
2. Fix shoulder shape before expanding choreography. Baseline audit found two left and one right inverted upper-arm triangles at 170 degrees, none at 0/90. Current cap is torso-fixed while almost all upper-arm vertices rotate fully; the deformation transition is too narrow.
3. Define shared attachment points and pose-dependent shoulder/sleeve corrections at 0/60/100/140/170 degrees. Preserve neutral, continuous up/down movement, sleeve thickness and head-height reach. Use compound corrections only where shoulder+elbow combinations actually need them. Do not hide defects by limiting the slider.
4. Separate geometry errors from missing artwork. Correct geometry with attachment/mesh work; request bounded new armpit, sleeve underside and cuff art when absent pixels are exposed. Record desired size, pivot, overlap, side and alpha/mesh contract before generating art.
5. Five-finger independence needs a palm, individual finger roots and appropriate open/half-curled/closed surfaces. Current strips and sleeve retraction are only a limited prototype; do not report them as anatomical fingers. Existing asset-request documentation overstates the loader: check-assets and --hand-kit paths are not yet implemented.
6. Rebuild performance: intentional gaze first, explicit rest-hold keys before head/torso follow, blink/eyebrow changes, distinct idle/listening/speaking states and bounded settling. Start with greeting/wave, curious listening and shy. Do not replace missing acting with continuous random wobble.
7. Preserve ownership/lifecycle: per-frame neutral reset; gesture ownership from compiled tracks; blinks multiply intended eyelid pose; audio alone controls ParamMouthOpenY; stop/reset/manual/reduced/dispose must clear secondary state. Preserve interruption continuity.
8. Verify both sides across continuous angle sweeps, one/both arms, shoulder+elbow combinations, bright/dark backgrounds and real WebGL playback. Test actual intended joins, not only nearest-vertex distance. The previous 0.03-unit elbow tolerance is roughly 89 source pixels and cannot prove a visually clean seam.
9. Retain existing 33 regression tests, add focused geometry and acting checks, and compare before/after renders at identical scale. A timer or changing slider is not proof of quality. Integration into live Jev and actual speech remains a later acceptance step.

## Publication and cloud boundary

Export only audited model source, synthetic tests, numerical rig configuration and this concise public-source brief into a fresh repository. Do not copy parent Git history, .env files, credentials, conversations, memory, session IDs, private logs, account names, local absolute paths, user screenshots or account usage evidence. Third-party original model/texture/Core/source binaries are not included in the public code export. No purchases or automatic recharge changes.
